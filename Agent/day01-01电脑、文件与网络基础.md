# day1-01电脑、文件与网络基础

## 一、文件系统：电脑的'图书馆'
电脑里的所有数据（照片、代码、文档、视频）都以文件形式存在，而文件夹（也叫目录）是用来整理这些文件的容器。

### 1、文件（File）
- 本质:存储在硬盘上的一段二进制数据(0和1)加上元数据(文件名、创建时间、大小、权限)
- 后缀名(扩展名):告诉操作系统用什么软件打开它(如.txt是文本，.py是Python代码，.jpg是图片)。**注意:后缀名只是“标签”，真正决定文件格式的是文件头部的魔法数字(Magic Number)**

### 2、文件夹（Directory/Folder）
- 本质:一个特殊的文件，里面保存着一张“清单”，记录着包含哪些子文件和子文件夹。
- 根目录:文件系统的“最顶层”(Windows是C:\或D:\，Mac/Linux是 / )。

## 二、路劲（Path）：文件的"家庭住址"
路径就是用来描述文件在文件系统中具体位置的字符串。搞懂路径，是操作终端和配置项目的前提。

| 类型 | 定义 | 特征标志 | 举例（Windows） | 举例（Mac/Linux） |
| :--- | :--- | :--- | :--- | :--- |
| 绝对路径 | 从根目录开始，完整且唯一的地址 | 以盘符或 / 开头 | C:\Users\Admin\Documents\report.docx | /home/admin/Documents/report.docx |
| 相对路径 | 从当前所在目录开始，描述如何找到目标 | 不以根目录开头，常用 . 和 .. | .\Projects\app.py 或 ..\images\pic.png | ./Projects/app.py 或 ../images/pic.png |

> 💡 **飞书划重点：**
> * `.` 代表当前目录。
> * `..` 代表上一级目录（父目录）。这在配置项目和跑脚本时极其常见。

## 三、终端 / 命令行（Terminal / CLI）：与电脑“裸聊”的方式

图形界面（鼠标点击）是给普通人用的；终端（命令行界面CLI）是给程序员用的“高效遥控器”。在服务器上，根本没有图形界面，全靠终端操作。

**必会的“四大金刚”命令（以Mac/Linux为例，Windows Git Bash同理）：**

| 操作目的 | Linux/Mac 命令 | Windows (CMD) | 说明 |
| :--- | :--- | :--- | :--- |
| 查看当前路径 | `pwd` | `chdir` | 我在哪？ |
| 列出目录内容 | `ls` | `dir` | 这里有什么？ |
| 切换目录 | `cd <路径>` | `cd <路径>` | 去某个地方（如 `cd ..` 返回上级） |
| 创建文件夹 | `mkdir <文件夹名>` | `mkdir` | 新建一个目录 |

> 🔥 **认知刷新：** 在终端里，回车键就是“执行”按钮。你输入的每一个字符，电脑都会严格解析，空格、大小写、斜杠方向都不能错。

## 四、服务器（Server）：提供服务的“高端电脑”

程序员写的代码最终要跑在服务器上，而不是你自己的笔记本上。

* **本质：** 服务器本质上就是一台配置更高、更稳定、7x24小时不关机的电脑。
* **客户端-服务器（C/S）模型：**
  * **客户端（Client）：** 发起请求的一方（你的浏览器、手机App）。
  * **服务器（Server）：** 接收请求、处理逻辑、返回数据的一方（网站后台）。
* **误区纠正：** “服务器”既指硬件（那台机器），也指软件（如Nginx、MySQL跑起来的服务进程）。我们常说的“部署到服务器”，就是把你的代码传到那台远程电脑上并运行起来。

## 五、端口（Port）：程序在电脑里的“门牌号”

一台服务器（电脑）上同时运行着无数个程序（Web服务、数据库、游戏）。当数据包到达这台电脑时，系统怎么知道该把这个数据交给谁？——答案就是端口。

* **本质：** 端口是 0~65535 之间的一个整数编号，用于标识电脑上特定的网络进程。
* **类比：** IP地址是“小区地址”（找到哪栋楼），端口是“几号楼几零几”（找到具体哪户人家）。

**极简端口分类（必须记住的常识）：**

| 端口范围 | 名称 | 常见用途 |
| :--- | :--- | :--- |
| 0 - 1023 | 系统/知名端口 | 需要管理员权限运行。如 80（HTTP）、443（HTTPS）、21（FTP）、22（SSH） |
| 1024 - 49151 | 注册端口 | 常见软件的默认端口。如 3306（MySQL）、6379（Redis）、8080（Tomcat/测试Web）、27017（MongoDB） |
| 49152 - 65535 | 动态/私有端口 | 操作系统临时分配给客户端（你的浏览器）使用的，用完即弃 |

> 💡 **面试/实战高频坑：** 部署项目时发现无法访问，90%的情况是端口没开放（防火墙拦截）或端口被占用。排查命令：`lsof -i:8080` (Mac/Linux) 或 `netstat -ano | findstr 8080` (Windows)。

## 六、本地网络（Local Network）：万物互联的起点

### 1. IP地址（Internet Protocol Address）

网络设备的唯一身份证。分为：

* **IPv4：** 由4组数字组成（如 `192.168.1.100`），总量约43亿个，已分配完毕。
* **IPv6：** 由字母数字混合的长串组成，解决地址枯竭问题。

### 2. 特殊的IP——127.0.0.1（Localhost）

* **含义：** 始终指向你自己的电脑本身。无论你是否联网，这个地址永远有效。
* **作用：** 用于本地测试。你在自己电脑上启动了服务 `python app.py` 监听端口 `8000`，在浏览器输入 `http://127.0.0.1:8000` 就能访问，而不用管外网IP是多少。

### 3. 局域网（LAN）与公网（WAN）

* **局域网IP**（如 `192.168.x.x` 或 `10.x.x.x`）：由你家路由器分配，只在你自已家里有效。
* **公网IP：** 由运营商分配，全世界唯此一份，这样才能被全球网民访问到。
* **NAT（网络地址转换）：** 你家的多台设备（手机、电脑）共用一个公网IP上网，路由器帮你做“翻译”。

## 七、终极实战推演：访问一个网页到底发生了什么？

把所有概念串起来，想象你在浏览器输入 `www.baidu.com` 并回车：

1. **DNS解析：** 浏览器把 `www.baidu.com`（域名）发给DNS服务器，获取百度服务器的公网IP地址（如 `110.242.68.66`）。
2. **端口指定：** 浏览器看到是 `http://`，自动使用80端口；如果是 `https://`，使用443端口。
3. **建立连接：** 你的电脑（随机分配一个临时端口，如 `54321`）向百度服务器（`110.242.68.66:80`）发起网络请求（TCP三次握手）。
4. **请求与响应：** 百度服务器上运行着Nginx软件，它一直监听80端口，收到你的请求后，找到对应的HTML文件，通过路径（如 `/index.html`）读出内容。
5. **页面渲染：** 百度服务器把数据打包，沿着网络线路传回你的电脑，浏览器解析并展示出美丽的搜索框。

## 八、写在最后：为什么这些“旧知识”如此重要？

在AI时代，Copilot能帮你写代码，但Copilot解决不了服务器路径配置错误、解决不了端口被占用、解决不了文件权限不足导致的崩溃。

* 当你理解绝对路径与相对路径，你就不会在项目迁移时满屏报错 `FileNotFoundError`。
* 当你理解端口和IP，你就能轻松配置Nginx反向代理，让前后端联调不再扯皮。
* 当你理解终端命令，你就敢直面Linux服务器那个黑乎乎的窗口，而不是只会用鼠标点来点去。

地基不牢，地动山摇。请务必打开你的电脑终端，亲手敲一遍 `cd`、`ls`、`mkdir`，把这节课的内容刻进肌肉记忆。
