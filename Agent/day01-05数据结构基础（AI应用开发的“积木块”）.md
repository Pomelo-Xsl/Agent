# day1-05数据结构基础（AI应用开发的“积木块”）

> 📌 适用读者：已经了解基础语法，但在处理API返回数据、配置Prompt参数时感到混乱的新手。
> 🎯 阅读收益：彻底搞懂列表、字典、对象、空值和返回值的底层本质；建立起“数据如何流动”的工程直觉；清晰掌握这5大概念在AI应用（如RAG、Agent、模型调用）中的具体落地点。

很多同学学完基础语法后，面对AI开源项目（比如LangChain、Dify）的代码依然一脸懵，不是因为看不懂 `if/else`，而是因为看不懂数据结构——数据被装在了什么“容器”里，怎么从A点搬到B点。

如果说基础语法是“动词”（做什么），那么数据结构就是“名词”（对谁做）。在AI应用里，数据在系统间的流动形态，决定了程序的智能上限。

### 一、列表（List / Array）：数据的“排队号码牌”

**核心定义**：列表是一个有序的、可变的数据集合，你可以往里面放任何类型的数据（数字、字符串、甚至其他列表），并通过下标（索引）来精准定位每一个元素。索引从 0 开始计数。

| 概念维度 | 通俗解释 | 代码示例（Python） |
| :--- | :--- | :--- |
| **定义** | 用一对方括号 `[]` 包起来，逗号分隔。 | `fruits = ["苹果", "香蕉", "橙子"]` |
| **取值（索引）** | 通过 `[数字]` 获取。`[0]` 是第一个，`[-1]` 是最后一个。 | `print(fruits[1])` 输出 "香蕉" |
| **遍历** | 用 `for` 循环逐个拿出来处理。 | `for item in fruits: print(item)` |
| **常用操作** | 追加（append）、删除（pop）、合并（+）。 | `fruits.append("西瓜")` |

🤖 **在 AI 应用中的 3 大核心用途：**

1. **批量输入（Batch Input）**：当你有一堆问题要问大模型时，放在列表里循环调用。
```python
questions = ["介绍一下杭州", "今天天气如何", "什么是RAG"]
for q in questions:
    response = llm.chat(q)  # 逐个发给大模型
```
2. **Embedding 向量（数字列表）**：AI 看不懂文字，只认数字。文本被转成的向量本质就是一个由浮点数组成的超级大列表（如 `[0.12, -0.56, 0.89, ...]`），维度通常为 768 或 1536。
3. **多轮对话上下文（Chat History）**：存储用户和助手交替发言的历史记录，按照时间顺序排队。

---

### 二、字典（Dict / Map / JSON）：数据的“带名牌的收纳盒”

**核心定义**：字典存储的是 **键值对（Key-Value Pair）**。你不再通过数字下标找数据，而是通过一个有意义的名字（Key）直接拿到对应的值（Value）。在AI领域，99%的API数据传输都靠它。

| 概念维度 | 通俗解释 | 代码示例（Python） |
| :--- | :--- | :--- |
| **定义** | 用花括号 `{}` 包起来，键和值用冒号 `:` 隔开。 | `person = {"name": "小明", "age": 25, "city": "北京"}` |
| **取值** | 通过 `["键名"]` 或 `.get("键名")` 获取。 | `print(person["name"])` 输出 "小明" |
| **特点** | 无序（Python 3.7+ 保留插入顺序），查找速度极快。 | 适合做配置信息和结构化数据传输。 |

🤖 **在 AI 应用中的 3 大核心用途：**

1. **模型调用的标准输入（Messages）**：调用大模型 API 时，消息体必须是字典结构。
```python
# 调用 OpenAI / DeepSeek 的标准格式
input_data = {
    "model": "gpt-4",
    "messages": [{"role": "user", "content": "你好"}],  # 这里嵌套了列表和字典！
    "temperature": 0.7
}
# response = requests.post(api_url, json=input_data)
```
2. **RAG 检索的元数据（Metadata）**：当向量数据库返回最相似的文档片段时，除了文本内容，还会附带来源、页码、作者等附属信息，这些全部用字典装载。
3. **Agent 的工具调用参数（Tool Call）**：当大模型决定要调用外部工具（如查天气API）时，模型会返回一个 JSON 格式的字典，里面包含 `{"function": "get_weather", "parameters": {"city": "杭州"}}`。

> 💡 **飞书贴士**：在 Python 中，`字典 (Dict)` 和 JSON 字符串长得几乎一样，区别在于：JSON 的键名必须用双引号 `"`，而 Python 字典可以用单引号。

---

### 三、对象（Object / Class）：数据的“活体机器人”

**核心定义**：如果说字典是“被动”的收纳盒，那么对象（实例）就是“主动”的实体。对象是属性（数据）和方法（功能）的集合体。它不仅能存数据，还能自带处理数据的行为。

| 概念维度 | 通俗解释 | 代码示例（Python） |
| :--- | :--- | :--- |
| **定义类** | 用 `class` 定义蓝图，规定有什么属性和方法。 | `class User: def __init__(self, name): self.name = name` |
| **实例化** | 根据蓝图造出一个具体的“活物”。 | `u1 = User("小红")` |
| **调用属性和方法** | 用点号 `.` 访问。 | `print(u1.name)` 或 `u1.say_hello()` |

🤖 **在 AI 应用中的 3 大核心用途：**

1. **封装复杂的 AI 模型客户端**：主流框架（如 LangChain）中，所有的 AI 模型都被封装成了对象。你不需要纠结底层 HTTP 请求，只需 `llm = ChatOpenAI()`，然后 `llm.invoke("问题")`。这里的 `llm` 就是一个对象，`invoke` 是它自带的方法。
2. **结构化输出（Structured Output）**：为了让大模型返回固定格式的数据（方便存入数据库），我们常定义 Pydantic 对象。让模型返回符合该类结构的对象，而不是随意的字典。
3. **多 Agent 系统中的角色扮演**：每个 Agent 都是独立的对象（拥有自己的记忆、提示词和工具集），它们之间通过对象方法进行通信。

> 🔥 **字典 vs 对象**：新手常常混淆。字典是纯粹的“数据行李”，简单但无脑；对象是“带着说明书的数据机器人”，不仅包含数据，还附带了操作这些数据的最佳函数。初期写脚本多用字典，后期写大型 AI 框架多用对象。

### 四、空值（None/Null/Nil）：数据的“真空地带”

**核心定义**：空值不是“0”，也不是空字符串 `""`，而是表示“这里没有任何有价值的数据”。它是变量被定义了，但还未被赋予有效值的状态。

| 语言 | 写法 | 注意事项 |
| :--- | :--- | :--- |
| **Python** | `None` | 首字母大写。`type(None)` 返回 `<class 'NoneType'>`。 |
| **Java / JSON** | `null` | 全小写。在 JSON 数据中极为常见。 |
| **JavaScript** | `null` | 全小写（此外还有 undefined）。 |

🤖 **在 AI 应用中的 3 大核心陷阱与用法：**

1. **处理 API 返回的缺失字段**：大模型 API 返回的 JSON 中，有些字段可能没有值（比如 `"error": null`）。你必须做判空处理，否则直接访问 `response["data"]` 会报错崩溃。
```python
result = api_response.get("error")  # 获取字段，即使不存在也返回 None
if result is None:  # 一定要用 is None，而不是 == None
    print("一切正常，没有错误")
```
2. **作为函数默认返回值**：如果函数没有写 `return`，Python 默认返回 `None`。这在 AI 流程编排中用于判断“该分支没有输出结果”，从而停止当前步骤。
3. **数据库中的空值**：在将 AI 生成的内容存入 SQL 数据库时，如果某字段没生成，存为 `NULL`（数据库概念），读取到 Python 中即为 `None`。

> ⚠️ **高频 Bug 警告**：`None` 不支持加减乘除和 `len()`。如果忘记判空，直接计算 `None + 5` 会报 `TypeError`。因此，拿到任何外部数据（尤其是大模型吐出来的 JSON）后，第一反应就是检查是否存在 `None`。

### 五、返回值（Return Value）：程序的“产出交接单”

**核心定义**：函数执行完毕后，交还给调用者的那个值。如果一个函数只是干活但不交还结果，那它就像默默工作的黑盒子，外界拿不到任何产出。

| 概念 | 解释 | 示例 |
| :--- | :--- | :--- |
| **有返回（return）** | 函数结束后，外面的变量可以接住结果。 | `def add(a,b): return a+b` -> `res = add(1,2)`（res 得到 3） |
| **无返回（void / 无）** | 函数内部自己处理完了，但不告诉调用者。 | `def print_hi(name): print(name)` -> 调用后只打印，但无法赋值给变量（得到 None）。 |

🤖 **在 AI 应用中的 2 种特殊模式：**

1. **同步返回（标准模式）**：你发送 Prompt，等待大模型算完，一次性把完整结果返回给你（如上述 `llm.invoke`）。适合生成文章、摘要、分类。
2. **流式返回（Streaming）**：AI 生成内容是一个字一个字“蹦”出来的。如果等全部算完再返回，用户会等待好几秒。因此，AI 框架支持迭代返回（`yield` / Generator），每次只返回一个“词块（Token）”。
```python
# 流式返回示例（伪代码）
def stream_chat(prompt):
    for chunk in llm.stream(prompt):
        yield chunk  # 不是 return，而是 yield，边生成边往外吐
# 前端收到第一个字就能立刻显示，体验极佳
```

### 六、终极串联实战：AI 应用如何把这些概念串在一起？

想象你在写一个智能客服 RAG 系统，看数据是如何流动的：

1. **输入列表**：用户发来一个问题（字符串），程序把它放入 `questions = ["商品怎么退货？"]`（列表）。
2. **检索参数**：为了去向量库找资料，构造查询参数（字典）：`{"query": "退货流程", "top_k": 3}`。
3. **检索结果**：向量库返回 3 个相关文档块，每个块包含内容和页码，存储为 `doc_list`（列表内部嵌套字典）。
4. **组装提示词**：将检索到的文本和用户问题拼接成 Prompt 字符串。
5. **调用模型**：封装好的模型对象 `llm`（对象）调用 `generate` 方法。
6. **判断空值**：如果网络不好，模型返回的 `response.text` 可能是 `None`，代码里用 `if result is None` 捕获异常，返回兜底话术。
7. **返回值输出**：最后，函数 `return final_answer`（返回值）给前端页面，显示在屏幕上。

### 写在最后：建立“数据容器”思维导图

不要死记硬背语法，请记住这张选择地图：

| 场景 | 该用哪个数据结构 |
| :--- | :--- |
| 需要处理一组有序的数据（多个文件、多个句子）。 | 列表 (List) |
| 需要用名字来标记数据（API参数、配置、用户信息）。 | 字典 (Dict) |
| 需要把数据和操作它的函数打包在一起（复杂功能模块）。 | 对象 (Object) |
| 判断某个字段是否存在、是否缺失。 | 空值 (None / Null) |
| 函数干完活后给调用者交代。 | 返回值 (Return) |

在 AI 时代，数据结构的理解能力直接决定了你能否看懂 `LangChain` 的源码和 `API` 文档。看到一堆方括号 `[]` （列表）和花括号 `{}` （字典）时，不要慌，先在脑子里画出它们的形状——这些容器装着的，就是 AI 的灵魂（数据）。
